## 第 0 步：先把 draft release 发布出去

**这一步不做，用户装不上。**

```
打开 https://github.com/nicholaskj/pin-indicator/releases
→ 看到 1.0.0，右边有 Draft 标记
→ 点铅笔图标 Edit
→ 滑到底，点 Publish release
```

发布后检查：页面上应该挂着 `main.js`、`manifest.json`、`styles.css` 三个文件。

---

## 第 1 步：注册 / 登录 Obsidian 账号

```
https://community.obsidian.md
右上角 Sign in
```

- 已有 Obsidian 账号 → 直接登录
- 没有 → 按提示注册（免费）

登录后进入 **Community profile** 页面。

---

## 第 2 步：关联 GitHub 账号

```
左侧栏 → Profile
找到 GitHub 区域 → 点 Connect
→ 跳转到 GitHub 授权
→ 同意（只给只读权限，用于验证仓库归属）
```

**不关联就没法提交**，这是硬性要求。

---

## 第 3 步：认领仓库

授权完会自动弹出 **Available to claim** 列表：

```
找到 nicholaskj/pin-indicator
☑ 勾选它
Claim as 下拉框选 Myself
→ 点 Claim 1 selected
```

---

## 第 4 步：提交插件

```
左侧栏 → Plugins → New plugin
```

表单只有两项要填：

| 字段 | 填什么 |
|---|---|
| **GitHub repository URL** | `https://github.com/nicholaskj/pin-indicator` |
| **Owner** | 选 **Myself**（不用和仓库 owner 一致） |

然后：
- 勾选同意 **Developer policies**
- 确认承诺「会持续维护，维护不了就下架或转让」
- 点 **Submit**

---

## 第 5 步：等自动审查

提交后系统会**自动审**，结果直接显示在目录页面：

```
✅ 通过 → 等人工复核 → 上架，用户能在 Obsidian 里搜到
❌ 有错 → 列表里显示具体问题
        → 改代码 → 推新版本 → 发新 tag → 建新 release
        → 会自动重新审（不用重新提交表单）
```

**注意**：改完必须发**新版本号的 release**（比如 1.0.1），不能只改仓库。

## 我们的插件对照官方政策（预检）

| 政策 | 我们的情况 |
|---|---|
| 不得混淆代码隐藏用途 | ✅ `main.js` 4KB 明文，一行没压缩 |
| 不得插入网络广告 | ✅ 无 |
| 不得有客户端遥测 | ✅ 无 |
| 不得自我安装/自我更新 | ✅ 无 |
| 网络使用需在 README 说明 | ✅ 完全不联网 |
| 账号付费需说明 | ✅ 不需要 |
| 访问库外文件需说明 | ✅ 不访问 |
| 必须有 LICENSE 文件 | ✅ MIT |
| 遵守原代码许可 | ✅ 独立开发，非 fork |
| 不得滥用 Obsidian 商标 | ✅ 插件名 Display Lock，id 不含 obsidian |

## 常见被拒原因（提前知道）

```
1. manifest 里的版本和 release tag 对不上
   → 我们有 workflow 自动校验，跑过就是对的 ✅

2. release 里没有 main.js
   → Actions 已上传三个资产 ✅

3. README 没写清楚怎么用
   → 中英双版，含用法、原理、安装、FAQ ✅

4. 描述开头写 "This is a plugin..."
   → 我们写的是 "Show a lock icon..." ✅

5. 描述结尾没句号
   → 有句号 ✅
```
